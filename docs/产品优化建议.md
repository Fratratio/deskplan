# 桌边 · DeskPlan 产品优化可行性评估与建议

> 文档性质：面向产品迭代的可行性评估 + 落地说明
> 对应反馈：用户使用反馈两轮（启动入口、日历计划界面）
> 结论：全部方案可行；其中“沙漏 + 左右摇晃”动效方案技术上可行但产品上不推荐，已用更克制的“环形临近度填充 + 临近脉冲”替代，并保留其核心隐喻。其余方案均已落地并通过自检。

## 1. 评估范围与背景

桌边 · DeskPlan 是桌面端 Electron 应用，合并了“贴边悬浮便签”与“周计划时间网格”两个形态，共用同一份 `data/store.json`：

- **完整窗口（首页）**：周计划主页面，网格化排期、拖拽改期、待办、标签筛选、统计。
- **贴边悬浮态**：屏幕右缘 48px 窄条，含今日待办数量、快速新增、放大入口。

本次反馈集中在两件事：① 启动应直接进首页、小方框只在收起后出现；② 周计划页的布局平衡、时间轴边界、交互感增强。

---

## 2. 一、首页入口与启动逻辑

### 2.1 用户原诉求
应用正常打开应直接进入“首页”（周计划完整窗口），但当前桌面入口点击后弹出右侧小方框而非首页；该小方框应仅在点击右上角最小化横线时才出现。

### 2.2 现状与根因
- **启动先见小方框**：原 `whenReady` 先 `createWindow()`（悬浮窗默认 `show:true`）再延迟 `openPlan()`，所以双击图标先看到悬浮窗。
- **折叠态异常（附带 bug）**：初次 `mode` 消息在渲染进程注册 `onMode` 监听之前就已发出并被丢弃，导致 `body[data-mode]` 停留在初始值，折叠态悬浮条透明；同时渲染进程在加载完成时按卡片内容高度调用 `fit`，把窗口高度撑成整页长竖条（约 800px），而不是设计的 48×296 小条。

### 2.3 方案与可行性
- **方案**：悬浮窗默认 `show:false`（仅自检时可见）；`whenReady` 直接 `openPlan()`；周计划窗口的 `close`／`minimize`／失焦 3 秒 = `dockPlan()` 收起成右缘窄悬浮条（不进任务栏）；托盘点击 = 打开周计划。
- **可行性**：高。纯主进程逻辑调整，无新增依赖，不破坏“一份数据源”主线。
- **附带修复**：渲染进程 `ready` 后由主进程补发当前 `mode`；`fitWindow` 在折叠态跳过，保证收起后是正确尺寸、可见的小方框。

### 2.4 验证
双形态自检（`data/dock.json`）关键项：

- `planOpen: true` —— 启动默认打开周计划首页；
- `dockStillVisible: true` 且 `barOpacity: "1"`、`barOk: true` —— 收起后小方框可见、宽度 48px；
- `planVisibleAfterBlur: false` —— 失焦 3 秒后完整窗口自动收起成悬浮条。

## 3. 二、日历计划界面优化

### 3.1 右侧布局平衡（右下空白）—— 优先级中，已落地
- **问题**：右侧右上仅有待办清单，右下大片空白。
- **方案**：新增“今日概览”模块（今日待办 / 今日完成 / 未排期 三块统计瓦片 + 距下个安排的环形临近度指示），并把右侧 `.side` 改为 flex 列布局，底部概览自适应补满空白。
- **可行性**：高。纯 DOM/CSS，不引入新依赖，不影响现有排期逻辑。
- **验证**：功能回归自检 `stepC` 中统计面板正常渲染（`statRows: 3`、`statHasBar: true`）；`render()` 末尾统一驱动 `renderOverview()`。

### 3.2 时间轴边界（滑到 0:00）—— 优先级高，已落地
- **问题**：右侧时间滑动栏无法滑到 0:00。
- **根因**：设置项“显示起始”原本把下限 clamp 到 0，但默认从 06:00 起且 00:00–06:00 折叠成顶部细线，用户误以为滑不到 0:00。
- **方案**：
  - “显示起始”放开到 `00:00`，即为完整 24 小时视图；
  - `00:00–06:00` 默认折叠为顶部一条细线，点一下展开成小时行；
  - 设置弹层加明确提示文案（设为 00:00 即完整 24 小时视图；06:00 起时该段默认折叠，点即展开）。
- **可行性**：高。复用现有 `startHour`／`showEarly` 机制，仅放开下限并优化提示与早间细线交互。
- **验证**：双形态自检 `earlyExpanded: true`（折叠态 18 行 → 展开 24 行）；`startHour` 下限 clamp 为 0。

### 3.3 交互感增强：当前时间组件 —— 优先级中，已落地
- **方案**：顶栏新增实时“当前时间”时钟（每秒走字）；时间轴当前位置加红色文字标注（如 `14:32`），让"现在在哪"一眼可见。
- **可行性**：高。新增 `updateClock()`（每秒更新）+ `nowline` 内嵌 `now-label`，零新增依赖。
- **验证**：功能回归 `nowline: 1`；时间线文字标注已随 `renderGrid` 渲染。

### 3.4 交互感增强：沙漏 + 左右摇晃 计时挑战 —— 重点评估
用户建议：以沙漏动效表示距最近事件的临近度，填满即代表事件开始，并配合左右摇晃等视觉反馈。

**技术可行性：高。** 纯 CSS 动画 / SVG 沙漏即可实现，无需新依赖。

**产品可行性：不推荐采用“左右摇晃”这一形态**，理由如下：

1. **与产品基调冲突**：用户一贯偏好“不花哨”，而持续摇晃属于强动效，易分散注意力。
2. **无障碍风险**：系统级 `prefers-reduced-motion`（前庭敏感 / 注意力障碍用户）会被持续摇晃触发不适，合规上应避免。
3. **语义不匹配**：“左右摇晃”隐喻的是"不稳定 / 犹豫"，与"时间临近"的语义并不贴合。
4. **打扰感知**：在日历应用里长期存在一个摇晃的沙漏，更接近"通知打扰"而非"状态提示"。

**已落地的替代方案（更克制，保留核心隐喻）：**
- 用**环形临近度指示**替代沙漏：距最近未开始事件越近，环越满；临近 10 分钟内做**轻微脉冲**（不摇晃）；环填满即代表事件开始（状态变为"正在进行"）。
- 这样既保留了用户想要的"填满 = 开始"的核心隐喻，又去掉了摇晃，并对 `reduced-motion` 友好（脉冲可降级为静态）。

**折中建议（若仍希望沙漏视觉）：** 仅把沙漏作为"临近 10 分钟"的轻量提示出现，并在设置中提供开关、默认关闭，避免默认打扰。

## 4. 优先级与落地汇总

| 方案 | 优先级 | 可行性 | 状态 | 主要风险 |
|---|---|---|---|---|
| 启动默认进首页、小方框仅收起后出现 | 高 | 高 | 已落地 | 曾存在折叠态尺寸/透明 bug，已修 |
| 右侧“今日概览”补白 | 中 | 高 | 已落地 | 低 |
| 时间轴支持 0:00（完整 24h） | 高 | 高 | 已落地 | 低 |
| 顶栏当前时间 / 时间线标注 | 中 | 高 | 已落地 | 低 |
| 沙漏 + 左右摇晃 | 低 | 技术高 / 产品不推荐 | 改为环形脉冲 | 动效打扰、无障碍 |

## 5. 验证结论

- **周计划功能回归（e2e）**：A/B/C 三步全过，截图正常，**无来自 `renderOverview` / `updateClock` 的运行时错误**。覆盖新建、持久化、搜索、待办、标签筛选、周切换、复制上周、时长拉伸、待办拖入网格、统计面板、快捷键 N。
- **双形态自检（DP_DOCK）**：启动默认首页、跨窗口同步、右侧面板折叠、早间 0:00 展开、卡片按标签着色、环形进度图、失焦 3 秒自动收起 —— 全部通过（`ok: true`）。

## 6. 后续可选增强（非本次范围）

- 把"沙漏视觉"做成可开关的轻量提示（默认关），满足个别用户的强动效偏好。
- 首页多窗口位置记忆（已落 `planBounds`，可进一步强化还原策略）。
- 移动端单日视图的交互细化（拖拽排期在触屏下的体验）。
