## 双形态怎么用

```
完整窗口态                                贴边悬浮态
┌──────────────────────────┐  最小化/     ╲ ╲ ╲ ╲ ╲ ╲ ╲ ╲ ╲ ╲ ╲
│  周计划 · 编辑/拖拽/排期  │  失焦3秒      ║ ＋  快速新增   ║
│                          │  ═══════▶    ║  3  今日待办   ║
│                          │  ◀═══════    ║ ›   放大 ═▶   ║
└──────────────────────────┘  点放大      ╲ ╲ ╲ ╲ ╲ ╲ ╲ ╲ ╲ ╲ ╲
                                鼠标悬停 ═▶ 展开今日小视图（备忘/今日两个标签）
```

- **默认进入首页**：启动（双击桌面图标 / 托盘图标 / `Ctrl+Shift+W`）直接打开周计划完整窗口。应用已在运行时再触发，同样只把首页叫到前台。
- **收起后才出现小方框**：右缘的 48px 窄悬浮条不在启动时显示，只在周计划窗口被最小化、或失焦超过 3 秒（托盘菜单可关掉这条）收起后才出现：今日待办数量 + 快速新增 `＋` + 放大 `›`。
- **进完整窗口**：双击桌面图标「桌边 DeskPlan」，或点托盘图标，或悬浮条上的 `›` 放大按钮，或 `Ctrl+Shift+W`。
- **侧边栏两个标签**：「备忘」是原来的便签列表；「今日」是今日日程 + 待办，支持回车快速新增、勾选完成、`排期` 一键放到今天最近的空档。点今日日程里的条目会打开完整窗口并跳到那一格。
- 周计划窗口开着时侧边栏自动安静贴边，不抢戏；托盘常驻，右键菜单含"失焦 3 秒自动收起"开关。

## 本轮产品优化（用户反馈落地）

针对使用反馈做了一轮优化，详见 `docs/产品优化建议.md`，技术改动集中在三处：

1. **启动默认进首页，小方框仅收起后出现**
   - 主进程改为悬浮窗默认 `show:false`、启动直接 `openPlan()`；周计划窗口关闭/最小化 = 收起成右缘窄悬浮条（不再进任务栏）。
   - 顺带修了一个潜在 bug：初次 `mode` 消息在渲染进程注册前被丢弃，会使折叠态悬浮条透明、且被内容高度撑成整页长竖条；现改为渲染进程 `ready` 后由主进程补发 `mode`，且 `fitWindow` 在折叠态跳过，保证收起后是正确尺寸、可见的小方框。

2. **周计划页布局与交互增强**
   - 右侧新增「今日概览」模块（今日计划 / 已完成 / 未排期三块 + 本周合计一行 + 距下个安排的环形临近度指示），补满右下空白；两张统计卡片都标清统计范围，避免"新增到别的日期却看着像没保存"。
   - 顶栏新增实时「当前时间」时钟（每秒走），时间轴当前位置加文字标注。
   - 时间轴边界放开：设置项"显示起始"支持 `00:00`（完整 24 小时视图）；`00:00–06:00` 默认折叠成顶部一条细线，点一下展开，设置弹层有提示文案。

3. **"沙漏 + 左右摇晃"方案的处理**
   - 该强动效与"不花哨"的基调冲突，且对 `prefers-reduced-motion` 用户不友好；改为更克制的环形临近度填充 + 临近 10 分钟轻微脉冲（不摇晃），保留"填满即代表事件开始"的核心隐喻。

4. **拖拽手感与落点修正（本轮）**
   - 新增网格坐标系唯一真源（`gridRange` / `pxToMin` / `minToPx` / `snapTo`），渲染、点空格新建、卡片拖拽、待办投放全部共用一套换算。之前各处各算一遍，早间时段展开后落点整体偏移 6 小时。
   - 拖动时卡片直接吸附到目标槽位（不再自由飘移），虚线占位上加实时时间标签，松手前就能看清会落到几点；抓取偏移全程保留。
   - 吸附粒度可配置（设置里的"吸附粒度"：5 / 10 / 15 / 30 / 60 分钟，默认 15）。
   - 目标列改按横坐标定位，不再依赖 `elementFromPoint`，光标拖出滚动区也能正确落列；拖出网格可视区时才自动滚动，避免画布乱动导致落点错位。
   - 松手后整屏重绘，时间标签、卡片排序与右侧统计同步刷新；拖动换时间支持撤销。

5. **右侧统计卡片修正（本轮）**
   - 统计口径收敛为两个函数（`dayStats` / `weekStats`），顶部状态条、「本周时间分配」「今日概览」都从同一处取数；新增 / 编辑 / 删除 / 拖拽 / 待办勾选后实时刷新，跨零点也会自动跟上。
   - 修掉"空档 126 小时（占可见时段 100%）"这种怪话：现在说的是"已排 X 小时 · 占可见时段 Y%"。
   - 空状态补齐：本周没安排时给出引导文案；今日没安排且没待办时，概览卡片提示怎么加第一条。
   - "距下个安排"会识别正在进行中的事件（原来只看未来，正在进行时显示"享受当下"）。

6. **桌面入口与图标（本轮）**
   - 修正 `tools/make_shortcut.py`：LinkInfo 的 LocalBasePath 指向目标文件本体（electron.exe）。之前填的是工作目录，Windows 把快捷方式解析成了文件夹，所以桌面上出现一个"只是图片"的假入口。
   - 重写 `tools/make_app_icon.py`：4 倍超采样 + 预乘降采样后逐尺寸输出 ICO（16/20/24/32/48/64/128/256）。上一版没做降采样，声明 256×256 的 PNG 里塞了 1024×1024 的行数据，Windows 解出来是花的——这正是"图标只是图片"的另一半原因。
   - 图案：圆角方块（黛蓝→铜渐变）+ 月历表头与两行圆点 + 右侧竖条（贴边侧边栏）。
   - 桌面只保留唯一入口 `桌边 DeskPlan.lnk`；旧的 `桌边.bat` 已移入回收站。

## 后续迭代记录（2026-10-12）

上一节六项之外，后续又落地了几轮，补齐于此：

1. **备忘卡片配色加深**：五色矿物色整体压暗、提饱和（黛 `#33587C` / 苔 `#467A4E` / 藕 `#6D4C85` / 铜 `#8F6432` / 朱 `#953F37`），卡片底色浓度由 10% 提到 30%（暮色 40%），文字对比度达 WCAG AA/AAA。详见 `docs/字体与配色样张.html`。
2. **字体替换**：瘦金体不可用，改为**华文行楷（STXingkai）**作为第二书法字体与楷体搭配，备选隶书、仿宋；字体档位现在为 默认/楷体/行楷/隶书/仿宋，两端设置均同步。
3. **悬浮窗质感修复**：不透明度/毛玻璃/纸张噪点三项此前失效——根因是 `theme-tokens.css` 里这些变量挂在 `html` 和 `body` 双作用域，而悬浮窗主题打在 `<body>` 上，只写 `documentElement` 会被 `body[data-theme]` 盖掉。现改为 `applyTexture()` 两端各写一份；噪点量程修正为 0–100、不透明度 20–100。
4. **标签筛选残留**：`plan.filterTags` 曾长期残留导致所有无标签卡片被压暗到 22% 不可见，用户误以为配色没生效。已清残留；筛选压暗从 22% 放宽到 50%，筛选生效时状态栏出现「清除」入口。
5. **字体两端同步修复**：`.mf`（正文内容字体类）原先只在 `app/plan/styles.css` 里有`font-family` 定义，悬浮窗的 CSS 完全没有这条规则。悬浮窗默认停在「今日」页，今日条目用的正是 `class="ttitle mf"`，所以在悬浮窗里切字体完全没反应。现已在 `widget/styles.css` 补上 `.mf`/`.ttitle` 等类，两端四档字体实测一致（`tools/fontsync.js`，正向反向均通）。
6. **皮肤系统（6 套）**：把原来的 `theme`（light/dusk 二选一）升级为 `skin` 维度，六套皮肤每套自带完整配色与CSS 纹理：

   | id | 名称 | 题材 | 底色 | 主强调 |
   |---|---|---|---|---|
   | `rice` | 宣纸 | 默认 | `#F4F2EE` | `#3A6489` |
   | `mist` | 青山 | 风景 | `#EDF2EE` | `#2E6B52` |
   | `sakura` | 樱SA | 动漫 | `#F6EFF3` | `#A6547C` |
   | `dusk` | 暮色 | 深色 | `#171A1F` | `#7FA3C4` |
   | `nebula` | 星野 | 航天 | `#14162A` | `#8FA8F0` |
   | `forge` | 熔炉 | 游戏 | `#1C1815` | `#D98B45` |

   - 颜色全部集中在 `app/shared/skins.css`，`theme-tokens.css` 退化为字体与版面令牌；两端 CSS 各引一份 `skins.css`。
   - 皮肤清单是唯一来源：`store-schema.js` 的 `SKINS` 导出给主进程，`widget/renderer.js` 顶部的 `S_SKIN` 与 `plan/app.js` 的 `SKINS` 是渲染侧副本（渲染进程开了 contextIsolation 且无打包器，不能 require 主进程模块）。**加皮肤要改三处**。
   - 周计划页的 `COLORS` 不再写死，改为 `refreshColors()` 运行时从 CSS 变量读，切皮肤时卡片与标签色自动跟着变。
   - 悬浮窗设置浮层新增皮肤网格（两列，每格带该皮肤三色预览色板）；周计划页设置弹层的「主题」下拉改为「皮肤」。
   - 纹理走 `.card/.sheet/.layout::before` + `--tex` 变量，只在有纹理的皮肤上生效，内容 `z-index:1` 保证不遮字。

## 桌面化改造（2026-10-12 晚）

把「能跑起来的 Electron 项目」改造成「真正可安装、双击即用的桌面应用」。

### 1. 任务栏与常驻

| 问题 | 原因 | 改法 |
|---|---|---|
| 启动后任务栏什么都没有 | 两个窗口都写了 `skipTaskbar: true` | 两端都改成 `false` |
| 任务栏名字显示「周计划备忘录」 | **HTML 的 `<title>` 会覆盖 BrowserWindow 的 `title`**，而任务栏文字用的正是窗口标题 | 两个 `index.html` 的 `<title>` 改成「桌边 DeskPlan · 周计划」/「桌边 DeskPlan · 悬浮窗」 |
| 应用会自己退出 | 没接管 `window-all-closed`（Electron 默认「所有窗口关闭即 quit」） | 显式注册该事件，非退出态一律不退出；退出只走托盘「退出桌边」或 `app:quit` |
| 托盘来回点没用 | `tray.on('click')` 不管状态一律 `openPlan()` | 改成 toggle（前台则收起，否则唤起），`double-click` 仍固定打开 |
| 重复双击图标开出第二个窗口 | 无——已有 `requestSingleInstanceLock`，补了 `app.setName()` 与 `appUserModelId` 便于任务栏分组 | 保留 `second-instance` 唤起已有窗口 |

现在：日历与小方框各自占一个任务栏位置（同一 `appId`，Windows 自动并组），点任一都能唤回；窗口收起来只是**最小化**，任务栏条目一直在。

### 2. 窗口关系（改造前两边互斥）

老逻辑 `dockPlan()` 同时做两件事——`planWin.hide()` + 强制悬浮窗收成窄条。结果是「打开小方块时日历被关掉，反之亦然」，正是用户说的「感觉像两个东西」。

现在拆开：

- `dockWidget()`：只收悬浮窗，绝不碰日历。
- `parkPlan()` / `dockPlan()`：只收日历（`minimize()` 而非 `hide()`），且必须由日历自己的关闭/最小化动作触发。
- `openPlan()`：窗口还在就 `restore()` 复用，**不重建**——重建会让页面重新加载，滚动位置、选中卡片、搜索词全丢。
- `showAndHold()`：只把悬浮窗叫出来，不隐式收日历。
- 「失焦 3 秒自动收起」默认**关掉**（`autoDock = false`），托盘里可开。

两个方向都有独立 IPC：`widget:show` / `widget:toggle` / `plan:show` / `plan:park`，preload 暴露为 `showWidget / toggleWidget / showPlan / parkPlan`。

### 3. 设置入口（原来只能在小方块里改）

周计划页的设置弹层里新增外观区，与悬浮窗共用同一套 UI：

- **皮肤**：六套色板网格（`#skinGrid`），每格带该皮肤三色预览，选中描 accent 边。
- **字体**：黑体 / 楷体 / 行楷 / 隶书 / 仿宋分段控件（`#fontSeg`）。
- 点一下即刻生效（`applySettings` → `save` → `render` → `pushShared`），没有「应用」按钮。
- 顶栏新增「小方块」按钮（`#toggleWidget`），点一下显示/收起桌面右侧的悬浮窗，日历本身不动。

样式 `.skin-grid / .skin-chip / .skin-sw / .skin-name / .seg` 已从 `widget/styles.css` 搬到 `app/shared/skins.css`——两个界面用同一套类名，样式必须放共享层，否则日历里一个定义都没有。

### 4. 分发安装

`package.json` 加了完整 `build` 段（electron-builder 25）：

安装器/卸载器/快捷方式图标都用 `assets/app.ico`（8 档尺寸 16→256）。`files` 白名单只放 `app/**` + 三个图标，但**单独留了 `tools/fullscreen-watch.ps1`**——主进程启动全屏监听时会引用它，排除掉会让「全屏时隐身」静默失效。

## 运行说明

### 安装使用（推荐，发给别人）

把 `release/DeskPlan-<版本>-x64.exe` 发过去，对方双击安装，桌面和开始菜单都会出现「桌边 DeskPlan」。

### 本机开发

```bash
cd deskplan
npm install
npm start        # 等价于 node_modules\electron\dist\electron.exe .
```

- **预期结果**：日历窗口弹出，任务栏出现两个条目（日历 + 悬浮窗），托盘有图标。
- 快捷键：`Ctrl+Shift+Space` 呼出侧边栏录入 · `Ctrl+Shift+W` 打开/聚焦日历 · `Ctrl+Shift+H` 显示/收起小方框。
- 托盘右键：唤起/打开周计划、显示或收起小方框、常驻展开、贴边、开机启动、打开数据目录、退出桌边。

> **npm 代理坑**：全局 `%USERPROFILE%\.npmrc` 里写了 `proxy=http://127.0.0.1:7897`，那个代理进程没在跑，所有安装都会 `ECONNREFUSED`。项目内已放 `.npmrc` 覆盖掉（`proxy=` / `https-proxy=`）。

### 浏览器 / 手机模式（可选）

```bash
cd deskplan
node serve.js          # 或双击 启动网页版.bat
```

- **预期结果**：控制台打出 `周计划主页面 → http://localhost:8777`；浏览器打开即为周计划页。
- `http://localhost:8777` → 周计划；`http://localhost:8777/app/widget/index.html` → 悬浮窗预览。
- 手机连同一 Wi-Fi 访问 `http://<本机IP>:8777`（≤780px 自动切单日视图）。
- 注意：浏览器模式数据在浏览器 localStorage，与桌面版 `store.json` 不同步（桥接只在 Electron 里生效）。

### 悬浮小方框如何自动显示（两种做法，本应用两种都做了）

1. **桌面端常驻（当前做法）**：主进程启动即创建无边框透明窗口，`alwaysOnTop` 常驻、`skipTaskbar:true`（不占任务栏，常驻托盘）、70ms 轮询鼠标位置决定收缩/预览/展开。参考了 GitHub 上 super-productivity 的 Task Widget 与 Cronus 的 floating window：都是"主进程持有常驻 widget 窗口 + IPC 控制显隐"，本应用沿用该模式。
2. **页面内自动挂载（浏览器模式）**：周计划页是普通网页，悬浮框在浏览器里就是 `/app/widget/index.html` 一个独立页面；若想把悬浮框挂进任意网页，引入 `theme-tokens.css` 后把 `app/widget/` 三件套作为组件加载即可——本项目未做额外打包，桌面端已覆盖需求。

## 数据与状态共享（怎么做到的）

```
悬浮窗 ──save(JSON)──┐
                     ▼
主进程 cache（内存） ──写──▶ data/store.json
                     ▲              │
周计划页 ──localStorage──┘          │
            （bridge.js 拦截         │
             'weekplan.v1' 这个键）  │
                                    ▼
        任一端写入后广播：摘要/外观 → 另一端即时更新
```

- 悬浮窗读写 `root.notes` + `root.settings`；周计划页读写 `root.plan`；皮肤与字体存 `root.shared`，任一端改动，另一端立即跟上。
- 周计划页代码一行没改：`bridge.js` 只拦截它原来用的那一个 localStorage 键。
- 旧 `memo.json` 首次启动自动迁入；`data/plan.import.json` 也会被自动并入。
