# 桌边 DeskPlan · 四项优化落地说明（2026-10-11）

对应需求：①计划拖动修复 ②启动方式清理 ③应用名与图标 ④右侧面板统计修复。
每项都先在无头环境复现 / 量化，改完再用同一脚本回归，结论附在各项末尾。

## 一、计划拖动修复

### 复现到的三个根因（改前实测）

| 现象 | 根因 |
| --- | --- |
| 早间时段展开后，拖到几点都整体偏移 6 小时（拖到 6:00 落到 12:00） | 拖拽换算把网格顶边当成「显示起始小时」，渲染却把顶边当 00:00，两处各算各的 |
| 拖到 23:00 这类深处时段落点丢失，再次拖回也不生效（一直停在旧时间） | 目标列靠 `elementFromPoint` 找，光标出了滚动可视区就取不到列，落点被直接丢弃 |
| 吸附名义上 30 分钟，实际只能落整点 | `Math.floor(y/H)*60` 先取整到小时，后面的 30 分钟取整形同虚设 |

### 改动内容

- **建立网格坐标系唯一真源**（`app/plan/app.js`，新增于「渲染：网格」之前）：
  `snapMin()`（吸附粒度，5/10/15/30/60 分钟，默认 15）、`gridRange()`（可见起止 + 早间展开后的真实顶边）、`pxToMin` / `minToPx`（像素 ↔ 分钟）、`snapTo`（吸附并夹在可见时段内）、`colAtX`（按横坐标定列）、`setEvLabel`（拖动中的实时时间文字）。
  渲染（`renderGrid`）、点空格新建、卡片拖拽、待办投放四处全部改用这一套，不再各算各的。
- **拖动反馈**（`window pointermove` 的 `move` 分支）：卡片本体直接吸附到落点（带 0.12s 过渡，手感跟手不生硬），另一条虚线占位同步吸附，占位左上角写实时时间段；横向换列也按坐标算。
- **松手落账**（`window pointerup`）：落点没取到也整屏重绘还原；成功后 `save(true) + render()`，时间标签、卡片排序（`layoutDay` 按 `startMin` 重排）、右侧统计一起刷新；toast 带撤销。
- **边缘自动滚动**：只在卡片被拖出网格可视区后才滚动（越远越快），光标在可视区内绝不滚动画布，落点不会跟手指错位。
- **拉伸（改开始 / 改时长）**：同样的吸附粒度与坐标系；`行高`、`显示起始`、早间展开与否都自动适配。
- **设置项**：`index.html` 设置弹层新增「吸附粒度」下拉（`#sSnap`），`app.js` 的 `DEFAULT.settings.snapMin` 与 `store-schema.js` 的默认值补齐该字段。

### 自动验证（`tools/dragtest.js` → `data/drag.json`）

10 个用例（常规 6 档 + 早间展开 4 档）全部通过：落点时间与目标完全一致，卡片渲染位置与落点偏差 `topDelta = 0`，拖动中卡片上的时间文字同步更新；拉伸用例通过（60 分钟 → 180 分钟）。

### 手动验证步骤

1. 双击桌面「桌边 DeskPlan」进首页，随便建一条 9:00 的计划。
2. 抓住卡片中上部慢慢拖：卡片会一档一档地吸附到时间格上，虚线框和卡片左上角的时间跟着变。
3. 松手后，卡片停留的位置、卡片上写的时间、详情弹层里的时间三者一致；把它拖到别天别的时间，右侧「本周时间分配」和「今日概览」的数字立刻变。
4. 设置 →「显示起始」改成 00:00（或点顶部早间细线展开），再把卡片拖到 3:00：落点就是 3:00，不再偏 6 小时。
5. 把窗口缩小让网格出现滚动条，把卡片往下滑到 23:00 附近拖动：拖到网格下缘外画布会自己往下滚，松手后时间正确。
6. 设置 →「吸附粒度」改成 60 分钟再拖一次，感受档位变化；改回 15 分钟。

## 二、启动方式清理

### 查明的事实

- 桌面上的 `桌边 DeskPlan.lnk` 是个坏快捷方式：`tools/make_shortcut.py` 写 LinkInfo 时把 LocalBasePath 填成了工作目录（应用文件夹），Windows 因此把它解析成文件夹，双击只是打开目录，图标也退化成默认图片样式——这就是那个「仅为图片」的入口。
- 另一个入口 `桌边.bat` 能用，但双击会闪一个控制台黑框，且和坏快捷方式重复。

### 处理结果

- 修好 `tools/make_shortcut.py`（LocalBasePath 指向 `node_modules\electron\dist\electron.exe`），重新生成了唯一的桌面入口并实测：ShellExecute 启动 → 主进程命令行为 `electron.exe  "<项目目录>"` → 首页正常弹出，验证后已清理进程。
- 旧的 `桌边.bat` 已**移入回收站**（没有直接删除，需要可还原）。
- **最终保留的唯一入口**
  - 文件名：`桌边 DeskPlan.lnk`
  - 完整路径：`桌面目录\桌边 DeskPlan.lnk`
  - 目标：`<项目目录>\node_modules\electron\dist\electron.exe`
  - 参数：`"<项目目录>"`　起始位置：`<项目目录>`　图标：`<项目目录>\assets\app.ico`

### 手动验证步骤

1. 看桌面：与桌边相关的图标只剩一个「桌边 DeskPlan」，图标是新画的月历样式。
2. 双击它：直接弹出周计划完整窗口（不打开任何文件夹、不闪黑框）；若应用已在运行，则只把首页叫到前台。
3. （可选）打开回收站，能看到 `桌边.bat`，确认不要了再清空。

## 三、应用名与图标

- **正式应用名**：沿用代码里的 `APP_NAME = 桌边 · DeskPlan`，快捷方式、托盘悬停提示、窗口标题、任务栏 AppUserModelId 四处一致，不做第二套叫法。快捷方式文件名叫 `桌边 DeskPlan.lnk`。
- **图标设计**（`tools/make_app_icon.py` 重写）：圆角方块打底，黛蓝（左上）到铜（右下）的斜向渐变；中间是一张月历——顶部粗横条是表头，两行圆点是排好的事；右侧一条竖条对应本应用最有辨识度的贴边侧边栏。16px 下仍能认出是"日历 + 侧边栏"。
- **格式**：`assets/app.ico`，内含 16/20/24/32/48/64/128/256 八档 PNG 压缩位图（ICO 容器），另出 `assets/app.png`（256）与 `assets/tray.png`（64，托盘用）。
- **顺带修掉的老 bug**：旧脚本超采样后没有降采样就写 PNG（声明 256×256、实际塞了 1024×1024 的行），Windows 解出来是花的——这就是之前图标"只是一张图片"的另一半原因。现在先按 4 倍超采样渲染，再做预乘 alpha 的盒子降采样，逐尺寸独立出图。
- **替换方式**：图标文件已直接覆盖 `assets/app.ico`；窗口与托盘图标是运行时读这个文件，重启即生效。桌面快捷方式的图标在重新生成 .lnk 时一并指向了新文件；若以后手动换图标，重新跑 `python tools\make_shortcut.py` 即可（Windows 有图标缓存，必要时先删掉旧 .lnk 再生成）。

### 手动验证步骤

1. 看桌面图标：月历样式清晰、边缘不糊；把桌面视图切到"小图标 / 大图标"各看一次。
2. 打开 `data\icon-preview.png`，一次看到 16/32/64/256 四档效果。
3. 启动应用后看任务栏（把托盘菜单里的"常驻最前"关掉就能看到）和托盘小图标，都是同一套图案。

## 四、右侧面板统计修复

### 查明的事实（探针 `tools/paneltest.js` 实测）

- 统计口径混乱：`今日概览` 只数"今天"的计划，`本周时间分配` 只数"本周"；把事件加到别的日期，概览三个数字永远是 0，看着像没保存上——这就是"新增事件后数量仍显示为 0"的主因。
- 文案离谱：没有安排时显示「空档 126.0 小时（占可见时段 100%）」——把睡觉时间全算成了空档，而且占比说的是空档不是已排。
- 空状态缺失：全空时只有三个 0，没有任何引导。
- 「距下个安排」只看未来事件，事件正在进行时反而显示"享受当下"。

### 改动内容

- **单一口径**（`app/plan/app.js` 新增 `dayStats(dateStr)` 与 `weekStats()`）：当日计划数 / 已完成 / 未完成 / 已排时长、本周条数 / 已完成 / 按标签时长聚合，全部从这两个函数取。顶部状态条 `renderStats`、「本周时间分配」`renderStatsPanel`、「今日概览」`renderOverview` 三处共用。
- **实时刷新**：新增 / 编辑 / 删除 / 拖拽 / 待办勾选本来就都走 `render()`；本轮再把 30 秒定时器从"只刷概览"改成整体重算四块，跨零点、"今日"口径自动跟上。
- **文案修正**：统计条改成 `本周 N 条（已完成 M）· X 小时 · 今日 K 条（已完成 J）· 待办 …`；时间分配卡片改为「已排 X 小时 · 占可见时段 Y%」。
- **空状态**：本周没安排 → 「本周还没有安排。在左边网格空白处点一下就能加一条」；今日没安排且没待办 → 概览卡片提示两条加入口。
- **概览补一行本周合计**：`本周共 N 条 · 已完成 M 条 · 今日已排 X 小时`——事件加到别的日期时这一行立刻动，不再让人以为没生效。
- **概览标注统计日期**（右上角小字 `MM-DD`），正在进行的安排显示「正在进行 · 14:00–15:00」并点亮临近脉冲。

### 自动验证（`tools/paneltest.js` → `data/panel.json`）

空 → 加 1 条（今日计划 1）→ 加到 2 条 → 标记 1 条完成（今日完成 1）→ 全删（归 0）→ 走真实 UI 点网格新建（落到 10-08 时，今日保持 0、但「本周 1 条」与已排时长立即变化）——每一步三张卡片的数字都同步正确。

### 手动验证步骤

1. 新建一条**今天**的计划：顶部状态条、右侧「本周时间分配」「今日概览」三处数字同时 +1。
2. 点开这条计划 →「标记完成」：「已完成」变 1，「今日计划」不变，时间分配里的完成数同步。
3. 删掉它：三处数字立刻 -1；全部删空后能看到两处空状态文案。
4. 新建一条**明天**的计划：今日概览保持 0 属正常（它统计的是今天），但概览里「本周共 N 条」和左上状态条会立刻 +1。
5. 打开右侧悬浮小方框加一条待办：计划页概览的「未排期」实时 +1；把它排期到今天，今日计划 +1、未排期 -1。
6. 把系统时钟跨过零点（或等到明天再看）：「今日」口径自动切到新的一天，不用重启。
