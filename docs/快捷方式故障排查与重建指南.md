# 桌面快捷方式：点不开、图标空白、双击进文件夹

适用现象：

- 图标看起来像空白纸/占位图，不像有效图片
- 双击后打开了一个文件夹，程序没启动
- 程序本身没坏，手动进目录运行正常

本文按“现象 → 根因 → 可执行排查 → 彻底重建”组织，Windows / macOS / Linux 各给一套命令。
可直接复制执行，路径换成你自己的即可。

---

## 0. 本次案例的实测结论（桌边 DeskPlan）

这台机器的环境：

| 项目 | 实测值 |
|---|---|
| 系统 | ProductName 报 `Windows 10 Home China`，DisplayVersion `23H2`，Build `22631.5624` |
| 架构 | AMD64 |
| 桌面真实路径 | `桌面目录`（未被 OneDrive 重定向） |
| 图标文件 | `<项目目录>\assets\app.ico`，27,689 字节，8 档尺寸齐全 |

Build 22631 属于 23H2 内核分支，注册表里的 ProductName 字段沿用了旧写法，按 22631 的行为处理即可。

三个症状对应的根因：

| 症状 | 根因 |
|---|---|
| 图标像空白图片 | 生成图标的脚本超采样后没有降采样就直接写 PNG，ICO 内容本身就是花的；Windows 解不出有效像素，退回占位图标 |
| 双击打开文件夹 | `.lnk` 里 LinkInfo 的 LocalBasePath 填的是应用目录 `<项目目录>`。Windows 拿到一个目录路径，就把这个快捷方式当文件夹入口解析 |
| 程序本体正常 | 目标文件 `electron.exe` 完好，问题全在快捷方式的三个字段上 |

**第三层根因（修完上面两个后仍然双击无反应，2026-10-11 深夜抓到）**：
生成脚本给 `.lnk` 置了"包含目标 IDList"标志位（LinkFlags 0x1），实际却写了一张空表
（总长只有 2 字节终止符）。Windows 解析快捷方式目标时**优先走 IDList**，
拿到空表目标就落空——LocalBasePath 写得再对也不看。表现：双击毫无反应，
干净环境下高速轮询（200ms 间隔）连一个进程都抓不到。修复：
用 `SHParseDisplayName` 让系统生成真实 PIDL 嵌进去（实测 IDList 从 2 字节变 691 字节，
双击 0.9 秒主界面弹出）；拿不到 PIDL 时宁可去掉 0x1 标志只留 LinkInfo，这也是合法写法。
体检脚本已加对应判定（`idListSize <= 2` 即报"需要重建"）。

修复后的字段（已实测双击直接进主界面）：

```
目标       <项目目录>\node_modules\electron\dist\electron.exe
参数       "<项目目录>"
起始位置   <项目目录>
图标       <项目目录>\assets\app.ico
```

Electron 这类应用有个固定坑：必须把 `electron.exe` 当目标、把应用目录当参数。
直接把应用目录当目标，或指向 `package.json`，都会被解析成"打开一个文件/文件夹"。

## 1. 症状与原因速查

| 症状 | 可能原因（按出现概率排序） | 十秒判读 |
|---|---|---|
| 图标空白、占位、白板 | 图标文件被删或移动；ICO 内容损坏；扩展名是 .png 但内容不是 PNG；图标路径用了 `%变量%` 但环境里没定义 | 把图标路径粘到资源管理器地址栏，看打不打得开 |
| 双击进文件夹 | 目标填的是目录；目标是 `.url`/`.lnk` 嵌套；扩展名被改错 | 右键 → 属性 → 看"目标类型"那一行 |
| 双击没反应 | 起始工作目录失效导致启动即退；程序需要参数但没传；杀软/智能屏幕拦截 | 手动在命令行里跑一次目标，看报什么 |
| 图标显示旧图 | Windows 图标缓存没刷新（重建了图标但桌面还是旧的） | 任务管理器重启 `explorer.exe` 后是否变化 |
| 提示无权限 | 目标在受保护目录（`C:\Program Files`）且没提权；UAC 拦截；文件被组策略禁执行 | 右键 → 以管理员身份运行 |
| 只在当前用户失效 | 快捷方式放在公共桌面但目标在用户目录；桌面被 OneDrive 重定向，改的是另一份 | 对比 `Desktop` 与 `OneDrive\Desktop` |

## 2. Windows 排查步骤

### 2.1 先确认你改的是不是真正的桌面

OneDrive 开启"桌面备份"后，用户桌面会被重定向到 `C:\Users\你\OneDrive\Desktop`。
在 A 处改快捷方式、在 B 处看图标，是排查半天没结果的典型原因。

```powershell
[Environment]::GetFolderPath('Desktop')
[Environment]::GetFolderPath('UserProfile')
```

两条输出不一致（第一条不在第二条下面），说明桌面被重定向了，后续所有操作都要用第一条的路径。

资源管理器里最直接的确认方式：桌面空白处右键 → 查看 → 勾选"显示文件路径"，或者随便拖个文件进去后在属性里看位置。

### 2.2 读出快捷方式的四个关键字段

**方法一：手动**
右键快捷方式 → 属性 → 快捷方式选项卡，看“目标”“起始位置”“快捷键”“备注”；再点“更改图标”看图标路径。

**方法二：PowerShell（推荐，但部分环境会拦 COM）**

```powershell
$s = New-Object -ComObject WScript.Shell
$l = $s.CreateShortcut("桌面目录\桌边 DeskPlan.lnk")
$l.TargetPath; $l.Arguments; $l.WorkingDirectory; $l.IconLocation
```

公司策略、CI、沙箱里 `New-Object -ComObject` 常被直接拒绝。
被拒时看报错关键词：`Retrieving the COM class factory` 或安全软件提示，就换方法三。

**方法三：纯二进制解析（不受 COM 策略影响）**

本项目自带体检脚本，照 MS-SHLLINK 规范直接读字节：

```bash
python tools/shortcut_doctor.py "桌面目录\桌边 DeskPlan.lnk"
```

输出会给出目标、参数、起始位置、图标，以及对这三项的逐一判定：

```
--- 目标检查 ---
  目标路径 : D:\...\electron.exe
  是否存在 : True
--- 工作目录检查 ---
  起始位置 : <项目目录>
  ok
--- 图标检查 ---
  尺寸档位 : 16x16@32bpp, 20x20@32bpp, ... 256x256@32bpp
--- 结论 ---
  三项均正常。若仍无法启动，问题在程序本身或权限，参看文档第 4 节。
```

抓坏样本的能力已实测：目标填成目录时会报 `目标是一个目录 → 双击只会打开文件夹，
这是"点图标进文件夹"的元凶`；起始目录失效时报 `目录不存在，程序可能启动即退`。

### 2.3 判目标：存在吗？是文件吗？可执行吗？

```powershell
$t = "<项目目录>\node_modules\electron\dist\electron.exe"
Test-Path $t                       # 存在？
(Get-Item $t) -is [System.IO.DirectoryInfo]   # 是目录？True 就是问题所在
(Get-Item $t).Extension            # 扩展名对不对
```

扩展名判定标准：`.exe/.com/.bat/.cmd/.msc` 可以直接启动；
`.lnk/.url` 属于嵌套快捷方式，需要再剥一层；其它扩展名会走"打开方式"对话框。

`.exe` 还得看有没有 PE 头（前两字节是 `MZ`）：

```powershell
$f = [System.IO.File]::OpenRead($t); $b = New-Object byte[] 2
$f.Read($b, 0, 2) | Out-Null; $f.Close()
[System.Text.Encoding]::ASCII.GetString($b)   # 应为 MZ
```

### 2.4 判起始工作目录

Electron、Python、Java 打包的程序普遍依赖当前目录找资源。
起始位置空着或指向不存在的目录，表现是"双击后闪一下就没了"。

```powershell
Test-Path "<项目目录>"   # False 就要改
```

修正原则：填**应用根目录**（`package.json` 所在层），填 `electron.exe` 所在的 `dist` 目录会让应用找不到自己的资源。

### 2.5 判图标

```powershell
$i = "<项目目录>\assets\app.ico"
Test-Path $i
(Get-Item $i).Length        # 0 字节必然空白
```

合法 ICO 的判定（脚本已内置）：

- 头部前 6 字节：`00 00 01 00 NN 00`，reserved 必须为 0、type 必须为 1
- 每档数据的 `offset + size` 不能超出文件长度
- 建议包含 16 / 20 / 24 / 32 / 48 / 64 / 128 / 256 八档；只有一档时，大图标视图会拉伸发虚

两种高频错误：

1. 把 `.png` 直接改后缀成 `.ico`。Vista 之后 Windows 支持 PNG 压缩的 ICO entry，
   但要求文件内部结构仍然是 ICO（有 ICONDIR 头）。纯改名文件没有这个头，图标就废了。
2. 生成工具超采样后忘了降采样，写进去的像素是错的。本次案例踩的就是这条。

图标路径还支持 `路径,索引` 写法（`app.ico,0` 取第一帧），脚本会自动剥掉索引再校验文件。

### 2.6 刷新图标缓存

换了图标文件，桌面还显示旧图，是 Windows 图标缓存在作怪，与快捷方式无关：

```powershell
ie4uinit.exe -ClearIconCache
taskkill /f /im explorer.exe
Remove-Item "$env:LOCALAPPDATA\IconCache.db" -Force -ErrorAction SilentlyContinue
Start-Process explorer.exe
```

提醒：`taskkill /f /im explorer.exe` 会关掉所有资源管理器窗口和任务栏，先保存手头工作。

### 2.7 被环境变量坑到：进程起来就崩，桌面毫无动静

这条排在最容易被忽略的位置。某些终端、IDE、脚本工具会往环境里塞：

```
ELECTRON_RUN_AS_NODE=1
```

它本来是给"拿 Electron 内置的 Node 跑脚本"用的。一旦被继承，Electron 应用启动时
`require('electron')` 返回的就只是一串路径，`app` 之类的接口全部不存在，进程在第一行
就崩掉，窗口根本来不及创建。外部看到的现象完全一样：双击图标，什么都没发生。

判断方法：命令行里手动跑一次目标，看有没有这类报错：

```
TypeError: Cannot read properties of undefined (reading 'setAppUserModelId')
```

确认变量来源：

```
shell 里看当前会话     echo %ELECTRON_RUN_AS_NODE%
注册表用户变量         HKCU\Environment
注册表系统变量         HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\Environment
```

只写进当前会话的话，资源管理器并不会继承，双击本来就不受影响；写进了注册表才会在登录会话里全局生效，去注册表删掉即可。

本项目已经在 `app/main.js` 顶部加了自愈：检测到 `require('electron').app` 不存在时，
自动清掉这个变量、用干净环境重启自身。带了这个保护之后，无论从哪个环境启动都能起来。

### 2.8 排到这一步还没解决

说明快捷方式没问题，往程序本体和权限查：

- 命令行里手动跑一次目标，看真实报错（GUI 双击会把错误信息吞掉）
- 应用日志（本项目的 `data/*.log`）
- 智能屏幕/SmartScreen：右键 → 属性 → 常规 → 底部若有"安全"提示需解除锁定
- 目标在 `C:\Program Files` 下且程序要写自身目录：提权，或把数据目录挪到 `%APPDATA%`
- 单实例锁：程序已有一个实例在跑，第二次启动会静默退出（本项目就有 `requestSingleInstanceLock`）

## 3. macOS 排查步骤

### 3.1 先分清是哪一类入口

```bash
ls -l@ ~/Desktop/你的应用
file ~/Desktop/你的应用
```

- 以 `.app` 结尾、且 `file` 显示 directory → 应用包（本质是目录，正常）
- `ls -l` 显示 `xxx -> /path` → 符号链接
- 带 `com.apple.FinderInfo` 扩展属性 → Finder 别名

符号链接和别名都能双击；符号链接在跨宗卷、目标移动后容易失效，别名更稳（记录了文件 ID）。

### 3.2 打不开的四类原因

```bash
# 1. Gatekeeper 隔离属性（从网上下载的应用最常见）
xattr -l /Applications/xxx.app
sudo xattr -dr com.apple.quarantine /Applications/xxx.app

# 2. 可执行权限缺失（自己打包、从压缩包解压出来的）
ls -l /Applications/xxx.app/Contents/MacOS/
chmod +x /Applications/xxx.app/Contents/MacOS/*

# 3. 签名损坏（提示"已损坏，无法打开"）
codesign -vvv --deep /Applications/xxx.app
codesign --force --deep --sign - /Applications/xxx.app

# 4. 架构不匹配（Apple Silicon 跑 x86_64 走 Rosetta）
file /Applications/xxx.app/Contents/MacOS/xxx
softwareupdate --install-rosetta    # 需要时
```

### 3.3 图标不显示

应用包需要 `Contents/Resources/xxx.icns`，且 `Contents/Info.plist` 里：

```xml
<key>CFBundleIconFile</key>
<string>xxx</string>    <!-- 不带 .icns 后缀 -->
```

改完重建图标缓存：

```bash
sudo rm -rf /Library/Caches/com.apple.iconservices.store
killall Finder
```

`.icns` 从 PNG 生成：

```bash
mkdir -p icon.iconset
sips -z 16 16   app.png --out icon.iconset/icon_16x16.png
sips -z 32 32   app.png --out icon.iconset/icon_16x16@2x.png
sips -z 32 32   app.png --out icon.iconset/icon_32x32.png
sips -z 64 64   app.png --out icon.iconset/icon_32x32@2x.png
sips -z 128 128 app.png --out icon.iconset/icon_128x128.png
sips -z 256 256 app.png --out icon.iconset/icon_128x128@2x.png
sips -z 256 256 app.png --out icon.iconset/icon_256x256.png
sips -z 512 512 app.png --out icon.iconset/icon_256x256@2x.png
sips -z 512 512 app.png --out icon.iconset/icon_512x512.png
sips -z 1024 1024 app.png --out icon.iconset/icon_512x512@2x.png
iconutil -c icns icon.iconset -o app.icns
```

### 3.4 重建入口

```bash
# 符号链接（命令行友好）
ln -s /Applications/xxx.app ~/Desktop/xxx
# 别名（Finder 里对 .app 按 Cmd+Option 拖拽创建，移动目标后仍能跟随）
# 放 Dock
defaults write com.apple.dock persistent-apps -array-add '<dict><key>tile-data</key><dict><key>file-data</key><dict><key>_CFURLString</key><string>/Applications/xxx.app</string><key>_CFURLStringType</key><integer>0</integer></dict></dict></dict>'
killall Dock
```

## 4. Linux 排查步骤

桌面图标走 XDG `.desktop` 规范，GNOME / KDE / Xfce 细节略有差异。

### 4.1 校验 desktop entry

```bash
ls -l ~/Desktop/xxx.desktop
desktop-file-validate ~/Desktop/xxx.desktop     # 没装：apt install desktop-file-utils
```

一份能用的最小配置：

```ini
[Desktop Entry]
Type=Application
Name=xxx
Exec=/opt/xxx/xxx                 # 必须绝对路径
Path=/opt/xxx                     # 对应 Windows 的"起始位置"，缺了会启动即退
Icon=/opt/xxx/icon.png            # 写绝对路径最稳
Terminal=false
```

### 4.2 不启动 / 不显示的三类原因

```bash
# 1. 没有可执行位，GNOME 会标"未受信任"
chmod +x ~/Desktop/xxx.desktop
gio set ~/Desktop/xxx.desktop metadata::trusted true

# 2. 图标路径不对（写图标名的话要装进图标主题目录）
cp icon.png ~/.local/share/icons/hicolor/256x256/apps/xxx.png
update-desktop-database ~/.local/share/applications
gtk-update-icon-cache ~/.local/share/icons/hicolor
killall nautilus      # 或 nemo / caja / dolphin

# 3. AppImage 需手动加可执行位；容器/沙箱环境常缺 FUSE
chmod +x xxx.AppImage
./xxx.AppImage --appimage-extract-and-run
```

### 4.3 重建入口

```bash
cp /usr/share/applications/xxx.desktop ~/Desktop/
chmod +x ~/Desktop/xxx.desktop
gio set ~/Desktop/xxx.desktop metadata::trusted true

# 或用官方工具
xdg-desktop-icon install --novendor /usr/share/applications/xxx.desktop
```

平铺窗口管理器（i3、Hyprland、dwm）本身不渲染桌面图标，桌面文件放上去也不会显示，需走 rofi / Ulauncher 之类的启动器。

## 5. 彻底重建一个"能显示图标 + 直接启动"的快捷方式

### 5.1 Windows 方法 A：脚本生成（推荐，不受 COM 策略限制）

用本项目的 `tools/shortcut_doctor.py`，先体检再重建：

```bash
# 体检
python tools/shortcut_doctor.py "桌面目录\桌边 DeskPlan.lnk"

# 重建（保留原文件为 .bak）
python tools/shortcut_doctor.py "桌面目录\桌边 DeskPlan.lnk" --fix ^
  --target   "<项目目录>\node_modules\electron\dist\electron.exe" ^
  --args     "\"<项目目录>\"" ^
  --workdir  "<项目目录>" ^
  --icon     "<项目目录>\assets\app.ico"
```

只想生成新快捷方式，直接用 `tools/make_shortcut.py`（本项目专用，路径写死在脚本顶部）。

写入时的两条硬规则：

1. LinkInfo 的 LocalBasePath 必须是**目标文件本体**。填目录会被解析成文件夹入口。
2. 起始位置填**应用根目录**，与 `electron.exe` 所在的 `dist` 目录区分开。

### 5.2 Windows 方法 B：PowerShell COM（正常环境最省事）

```powershell
$desk = [Environment]::GetFolderPath('Desktop')
$s = New-Object -ComObject WScript.Shell
$l = $s.CreateShortcut((Join-Path $desk '桌边 DeskPlan.lnk'))
$l.TargetPath       = '<项目目录>\node_modules\electron\dist\electron.exe'
$l.Arguments        = '"<项目目录>"'
$l.WorkingDirectory = '<项目目录>'
$l.IconLocation     = '<项目目录>\assets\app.ico,0'
$l.Description      = '桌边 · DeskPlan'
$l.WindowStyle      = 1      # SW_SHOWNORMAL
$l.Save()
```

被 COM 策略拦截时改用方法 A 或方法 C。

### 5.3 Windows 方法 C：手动

1. 资源管理器进到 `electron.exe` 所在目录
2. 右键 `electron.exe` → 显示更多选项 → 发送到 → 桌面快捷方式
3. 回到桌面，右键新快捷方式 → 属性
4. “目标”末尾追加 ` "<项目目录>"`（注意前面有空格）
5. “起始位置”填 `<项目目录>`
6. “更改图标”→ 浏览 → 选 `assets\app.ico`
7. 确定，双击验证

### 5.4 重建后必做

- 桌面还显示旧图标：执行 2.6 的清缓存三步
- 双击仍然进文件夹：说明“目标”被改回目录了，回到 2.3 复查
- 双击闪退：命令行手动跑一次目标看报错（2.7）

### 5.5 macOS / Linux 重建

分别见 3.4 与 4.3。

| 图标文件实际路径与来源 | 自己生成的、从 exe 里提取的、还是网上下载的。用于判断是格式问题还是路径问题 |
| 双击后的具体表现 | 打开的是哪个文件夹、有没有报错弹窗、有没有安全软件提示 |
| 是否多用户 / 公司域环境 | 组策略可能禁 COM、禁执行、重定向桌面 |
| 是否开启 OneDrive 桌面备份 | 决定有两份桌面时要改哪一份 |
| 程序手动运行是否正常 | 区分是快捷方式问题还是程序本身问题 |

给这些信息时，最好附上：资源管理器里“属性 → 快捷方式”四个字段的截图，
以及命令行手动运行目标时的完整输出。

## 7. 体检脚本速查

```
python tools/shortcut_doctor.py <link.lnk>                    诊断
python tools/shortcut_doctor.py <link.lnk> --fix --target X   重建（可选 --args/--workdir/--icon）
python tools/shortcut_doctor.py --platform macos              打印 macOS 排查顺序
python tools/shortcut_doctor.py --platform linux              打印 Linux 排查顺序
```

检查覆盖：文件是否为空或伪格式、目标是否存在且非目录、目标是否带 PE 头、
起始目录是否存在、图标路径与 ICO 头合法性、尺寸档位是否齐全。

脚本不依赖 COM，在受限环境里也能跑；源码在 `tools/shortcut_doctor.py`，
字段解析照 MS-SHLLINK 规范实现，可按需改造成批量体检。
